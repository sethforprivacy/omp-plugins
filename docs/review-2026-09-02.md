# Hardening review — 2026-09-02

A review pass over the bundle after ~12 real runs and 3 benchmark iterations. Sources: the
repo itself, every OMP session transcript that spawned a `rev-*` seat (Aug 13 → Aug 31),
`~/.omp/logs`, the saved results/reports under `~/.omp/{quorum-review,security-quorum}`, the
sibling `omp-pilotfish` plugin (incl. its v0.2.0 trace-review branch), and a survey of the
better-documented multi-model review tools (zen-mcp, llm-council, Star Chamber, Anthropic's
claude-code-security-review and Claude Code review, PR-Agent, BugBot, Codex review rules).

## What the traces showed (12 real runs, ~60 seat spawns)

**The protocol was right; the orchestrator kept drifting off it.** Every real panel was
spawned as one batch, but around it:

| Drift observed | Runs | Fix shipped |
|---|---|---|
| Local `scout` agents used as "the panel" (user corrected it live) | 1 | seat files are now leaves (no `spawns:`), SKILL.md rule + lint |
| Two identical `task` calls in one message → 6 spawns for a 3-seat panel | 1 (+ scout pre-checks) | explicit "ONE task call per round" rule |
| `panel.mjs` skipped, seat list hardcoded from memory | 1 | panel snapshot is step 2 and feeds `dedupe --panel` |
| `dedupe.mjs` skipped entirely | 3 | dedupe is the only path to denominators/provenance now |
| Results re-typed by hand (317–547 B files, `findings: 0`) instead of saved verbatim | 1 | "save raw `result.data`" rule; dedupe warns on transcribed shapes |
| Results not saved at all (whole rounds) | 3 rounds | same rule; `--panel` shows the hole as "no result" |
| Packet built 4× for one round; wrong skill's `packet.mjs` used once | 2 | "exactly once per round", absolute script paths |

**Seat failures were behavioural, not routing, after the nanogpt switch (2026-08-25).**
Zero provider 4xx/5xx on nanogpt in the retained logs. What did fail: `schema_violation`
after a *complete* review (glm: `confidence` as an array, verdict enum), some costing 14–24
minutes; and glm security seats that never yielded (36 and 39 minutes of prose). Pre-switch,
OpenRouter 402 credit flaps killed whole panels in under 40 s.

**Corroboration almost never formed.** 8 of 8 saved reports are dominated by single-reviewer
findings (e.g. 1 corroborated / 8 single). Two mechanical causes were found in `dedupe.mjs`:
seats cite the same file as `/abs/path/x.cs`, `x.cs` or `src/x.cs` and the old exact-key match
never clustered them; and the report sorted by **file path first**, so a P0 in `z.cs` sat
below P3s in `a.cs`. Both fixed (suffix-tolerant path match; priority-first ranking with a
single-seat P0/P1 callout).

**Verdict-only fast seats are real.** All four seats on one run returned `findings: []` at
0.86–1.0 confidence; `rev-quorum-gem` returned zero findings in every 08-20 run. This matches
the benchmark: weight gem's findings, never its verdict.

**Packet budgeting never triggered** (`0 over-budget` in every run) but per-file truncation at
100 KB did, and the orchestrator spent a minute grepping to check what was cut. `packet.mjs`
now lists truncated files explicitly on stderr and in `--json`.

**Two observations outside this repo, for the owner:** `~/.omp/agent/config.yml` carries stale
`task.agentModelOverrides` keys (`reviewer`, `security-reviewer`) for agents that no longer
exist; and one session transcript under `~/.omp/agent/sessions/-repos-work-cake_wallet/`
(2026-08-17) contains a 24-word seed phrase in plaintext.

## OMP mechanics that decide the design

- `task` has **no per-spawn `model` parameter** (removed upstream). Model resolution order:
  `task.agentModelOverrides.<agent>` → agent file `model:` → session model. A per-spawn
  `effort` hint (`lo|med|hi`) exists but only when `task.enableEffort` is on (it is off).
- A model with no working credentials makes OMP **fall back to the parent session's model**
  (`resolvedModelIsFallback: true`). For a quorum that is a silent loss of independence, so the
  protocol now treats a fallback result as a failed seat and `dedupe --panel` flags it.
- `omp --config <overlay.yml>` applies a config overlay to one session. `omp config get` does
  not see overlays, so `panel.mjs` can only show *persisted* overrides — the delivered result's
  resolved model is the source of truth.
- Selectors accept a thinking suffix (`provider/model:high`) and `@role` aliases.
- Seat sessions on nanogpt record `thinking_level_change → high` for `rev-sec-glm`
  (pinned `xhigh`): the route clamps the level. The xhigh pin is effectively `high` on nanogpt.

## What changed in this pass

Scripts:
- `panel.mjs` — shows the **effective** model (seat pin or `task.agentModelOverrides`), honors
  `task.disabledAgents`, reads list-form/alias `model:`, `--json` now `{ seats, skipped, notes }`.
- `packet.mjs` — secret-like filenames (`.env*`, keys, `*token*`, `*secret*`, …) and binary
  files are listed but never embedded (override: `--all-files`); header carries `rev`,
  `branch` and a `fingerprint` (sha256 of exactly what the seats see); truncated files are
  listed on stderr and in `--json`; probe stderr silenced; a "data under review, not
  instructions" banner above the diff.
- `dedupe.mjs` — `--panel <panel.json>` / `--expected`: missing seats appear as "no result" and
  denominators use the active panel; resolved-model vs panel cross-check; fallback flag;
  suffix-tolerant path clustering; priority-first ranking with a single-seat P0/P1 callout;
  tolerant parsing of transcribed results (`severity: "P1"`, `area`, string verdicts) with a
  warning; non-result JSON skipped instead of ingested as a phantom reviewer.
- `lint.mjs` (new) — seat/skill consistency: name == filename, model selector shape, no write
  tools, no `spawns:`, yield shape + injection guard + leaf guard present, category enum equal
  across a family and between schema and body, strict-YAML-safe scalars, scripts parse.
  `install.sh` runs it first and refuses to install a failing bundle (`--no-lint` to force).

Seats (all ten): `spawns: scout` removed (a seat that delegates runs part of its review on the
local model); leaf guard + repo-conventions line added (findings resting on a project rule
must cite it — the Codex custom-rules result, 98% vs 58% recall on rule-driven findings);
findings must state how they were verified; security seats gained a `<precedents>` block
(safe-by-default assertions distilled from claude-code-security-review's FP filter);
descriptions say `(nanogpt)`.

Skills: both SKILL.md files rewritten as a shorter, step-numbered checklist with the hard
rules the traces showed being broken, the provenance check, verbatim-save rule,
`schema_violation` handling, `--panel` dedupe, fingerprint-differs rule for verify passes,
and a "swapping seat models on command" section. Dated "pending live validation" notes moved
out (the 2026-08-20 benchmark validated them).

New: `presets/` — `override-template.yml`, `local-only.yml`, and a README on the three
override scopes (session overlay, repo config, global/`/agents`).

## Recommendations 1–4 — implemented in the same branch (2026-09-02, later the same day)

1. **Refutation pass.** `minipacket.mjs --mode refute` builds an anonymized packet of the deduped
   findings with the cited code (corroboration counts and reviewer identities hidden); one
   non-reporting seat must answer `CONFIRMED — <trigger path>` or `REFUTED — <why>` per finding;
   `dedupe.mjs --refuted` marks verified findings and moves refuted ones to a "shown, not
   actioned" section. Optional step 6b in both SKILL.md files; also mechanizes the arbitration
   mini-packet (`--mode arbitrate`), which was hand-written before.
2. **Plugin packaging.** Repo restructured to `.omp-plugin/marketplace.json` +
   `plugins/quorum-review/{agents,skills,presets}`; shared scripts live once, in the
   quorum-review skill dir, and both SKILL.md files resolve the path at run start (plugin cache
   first, manual copy second). `scripts/validate-marketplace.mjs` + CI (SHA-pinned actions,
   read-only perms) run lint, validation, a dry-run install and script smoke tests.
   `install.sh` stays as the manual fallback and gained `--uninstall` (manual copies shadow the
   plugin by name).
3. **Runtime backstop.** `presets/backstops.yml` sets `task.maxRuntimeMs` (45 min) and
   `task.showResolvedModelBadge`; both SKILL.md files point at it.
4. **Context expansion when under budget.** `packet.mjs` builds the diff with 12 lines of hunk
   context and falls back to 3 only if the wider diff would not fit the budget; the stderr line
   reports which (`context N`), `--context <n>` pins it.

## Explicitly not added (and why)

- **Multi-round debate / stances in the primary round.** Evidence is anecdotal or negative
  (models converge on shared wrong answers; a seat told to argue "against" manufactures
  findings). One anonymized arbitration round is the defensible version and already exists.
- **Chairman/LLM synthesis replacing `dedupe.mjs`.** Loses determinism for no measured gain.
- **Confidence as a gate.** Self-reported confidence is miscalibrated, worst on security
  (gem at 1.0 on defective code). It stays a sort hint.
- **Per-seat "lens" assignment.** Intuitive, unproven, narrows each seat's recall. Benchmark
  it with the seeded-defect harness before shipping.
- **Randomized per-seat file order.** Contradicts the "same brief to every seat" invariant that
  makes corroboration meaningful.
- **Alias-first `model:` lists in seat files.** pilotfish v0.2.0 does this (`@pf-strong` then
  a concrete fallback). For a per-vendor panel the natural knob is the per-seat override, and
  a list's silent fallback to a different model is exactly what a quorum must not do.
- **Changing the one-finding-per-yield contract.** pilotfish measured 13 schema retries across
  10 runs with an *incremental-sections* instruction and moved findings into the final payload.
  This bundle's contract is different (one finding per `yield`, verdicts as separate bare
  yields) and delivered 39/39 structured results on the benchmark; the real-run failures were
  enum/type violations, not the sectioning. Left as is; revisit if `schema_violation` recurs.
- **A learned triage router.** Rules capture most of the benefit; the "docs-only diff" check in
  SKILL.md is the rule.
